# Windows 自启动修复工具

修复「应用设置了开机自启,却不开机启动」的常见故障。PowerShell 5.1 + WinForms 编写,Win10 自带环境零依赖,无需安装任何东西。

## 使用方法

**方式一(推荐):** 在 [Releases](../../releases) 下载 `StartupRepair.exe`,双击运行,在 UAC 弹窗中同意提权即可。exe 由 ps2exe 打包、未签名,浏览器或 Windows 可能提示「已保护你的电脑」(SmartScreen),点击「仍要运行」;如被安全软件拦截,请自行判断信任,或改用方式二。

**方式二:** 双击 `StartupRepair.bat`(需要与 `StartupRepair.ps1` 同目录),同样自动请求提权。

- **重新扫描**:读取全部自启位置,重新生成列表
- **修复选中项**:对勾选的条目执行修复。执行前会弹出确认清单,并自动备份到 `backups\` 目录,可随时恢复
- **全量备份**:把所有相关注册表项(.reg)、启动文件夹、计划任务 XML 完整导出到 `backups\`
- **从最近备份恢复**:用最近一次修复前的快照回滚
- **打开备份目录**:直接打开 `backups\` 文件夹
- 双击任意行:在资源管理器中定位该程序文件

默认勾选「只显示异常项」,取消勾选可查看全部条目。

只读命令行模式(不弹界面、不做任何修改):

```
powershell -NoProfile -ExecutionPolicy Bypass -File StartupRepair.ps1 -ScanOnly
```

## 扫描覆盖的位置

| 位置 | 说明 |
|---|---|
| 注册表 Run · 当前用户 | `HKCU\...\CurrentVersion\Run` |
| 注册表 Run · 所有用户 | `HKLM\...\CurrentVersion\Run`(64 位与 32 位 WOW6432Node) |
| 启动文件夹 · 当前用户/所有用户 | `%APPDATA%` / `%ProgramData%` 下的 Startup 文件夹 |
| 计划任务 · 登录时 | 登录/开机触发、非 Microsoft 的计划任务 |
| 残留标记 | `StartupApproved` 中条目本体已不存在的标记 |

## 诊断与修复对照

| 状态 | 含义 | 修复动作 |
|---|---|---|
| 已禁用 | 在任务管理器/设置中被关闭 | 重新启用启动项 |
| 需要管理员权限 | 程序要求提权,挂在 Run 键会被系统静默跳过 | 转为计划任务(最高权限)并移除原条目 |
| 任务已禁用 | 计划任务被禁用 | 启用计划任务 |
| 文件缺失 | 目标程序不存在 | 仅报告;勾选后可删除失效条目 |
| 任务目标缺失 | 计划任务指向的程序不存在 | 删除失效任务(勾选) |
| 残留标记 | 自启条目本体已被删除 | 仅报告;勾选后可清理标记 |

## 安全设计

- 任何修复前自动备份到 `backups\<时间戳>\`(含 `backup.json` 快照 + 被删文件副本 + 计划任务 XML)
- 修复前弹出确认清单,逐项列明操作内容
- 「转计划任务」会先创建任务并验证状态,成功后才移除原注册表条目
- 备份保留不自动清理,需要时手动删除旧目录

## 已知限制

1. **被彻底删除的条目无法自动恢复**——注册表里已没有原命令(如清理软件删掉的 EA app、向日葵的自启),工具只能报告残留标记。恢复办法:在应用自己的设置里重新开启「开机启动」,或使用本工具的历史备份。
2. **重装/升级应用可能抹掉自启条目**——MSI 卸载会顺手删掉应用注册的 Run 条目,重装后往往不会重新注册(cc-switch 就是这种情况)。扫描会显示残留标记,修复前建议先「全量备份」。
3. 修复在**下次登录**时生效,当前会话不受影响。
4. 「需要管理员权限」的判定基于程序内嵌清单资源的第一个 requestedExecutionLevel 声明,个别自带多份清单模板的程序(如 Lossless Scaling)已做过兼容,一般不会误报;修复前请仍以确认清单为准。
5. 计划任务的完整枚举需要管理员权限,请始终通过 StartupRepair.bat 启动。
